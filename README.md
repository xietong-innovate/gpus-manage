# GPU 管理系统（gpus-manage）

共享 GPU 集群的**显卡级实时监控与管控系统**：把所有 GPU 机器的 IP 一次性绑定进系统，实时掌握每张显卡的状态、显存、温度与占用进程，管理员可随时安全地终止任意显卡上的进程。全部数据经 SSH 直连（或本机直连）实时采集，无 Kubernetes、无作业排队体系。

> 本项目由微软开源项目 [microsoft/pai（OpenPAI）](https://github.com/microsoft/pai) 深度魔改而来，仅保留并重写了 GPU 管理所需的核心能力。

## 功能特性

- **节点接入**：粘贴 IP 清单一次绑定全部 GPU 机器，四步接入验证（网络可达 → 登录验证 → GPU 清单采集 → 登记显卡档案），失败行不阻断整批
- **实时监控**：5 秒周期采集每张显卡的已用/总显存、利用率、温度、ECC 错误；状态自动流转（空闲 / 占用中 / 故障 / 状态未知），SSE 推送前端免刷新
- **进程明细**：每张显卡的占用进程一目了然——PID、属主、命令行、运行时长、**Python 虚拟环境识别**（conda:xx / venv:xx / system-python）
- **进程终止**：管理员两段式终止（优雅信号 → 宽限期 → 强杀兜底），PID 二次确认防误杀，同一进程 1 分钟内最多 3 次重试，全程写审计
- **硬件变更检测**：换卡/加减卡自动告警，变动卡位转为状态未知，待管理员确认档案后恢复
- **凭据安全**：节点 SSH 凭据 AES 加密存储、永不回显；管理员密码 bcrypt 加密；登录连续失败锁定
- **审计日志**：只增不改不删，谁在什么时间对哪张卡做了什么全程可查

## 环境要求

| 组件 | 要求 |
|---|---|
| 服务端 | Node.js ≥ 18（无需构建，无数据库） |
| Linux GPU 节点 | 可 SSH 直连，账户能读取任意进程的 `/proc` 信息并 kill 任意进程（通常为 root）；已安装 NVIDIA 驱动（`nvidia-smi` 可用） |
| Windows 本机节点 | 绑定 `127.0.0.1` 即可，无需开启 SSH，系统直接在本机执行采集与终止 |

## 使用指南

### 1. 绑定 GPU 节点

进入「节点管理」页：

- **批量绑定**：每行一个 `IP` 或 `IP:端口`（默认 22），整批共用一套 SSH 凭据（加密存储，永不回显）。可先点「解析并校验」预览有效行，再点「开始接入」
- **本机直连**：填 `127.0.0.1`（或 `localhost`）即可接入本机 GPU，无需填写任何凭据
- **新增单个节点**：适合临时补充机器
- 绑定后系统自动执行四步验证并登记发现的显卡，进度实时显示在页面上

### 2. 总览页看什么

- 顶部汇总标签：**总卡数 / 空闲 / 占用中 / 故障 / 状态未知**——点击标签可筛选对应状态的显卡，再点一次取消筛选
- 每张显卡卡片：型号、总显存、已用显存（进度条）、利用率、温度、进程数
- **点击卡片下钻**：查看该卡全部占用进程（PID、属主、虚拟环境、显存、运行时长、命令行摘要），以及「其他/系统占用」= 卡已用 − Σ进程（驱动上下文与碎片开销）
- 无进程但显存高于空闲阈值（默认 500MB）的卡会标记「疑似泄漏」
- 页面顶部出现橙色「硬件变更待确认」提示时，说明该节点换卡/加减卡，去节点管理页点「确认档案」即可恢复

### 3. 终止进程（管理员最高权限）

在下钻明细中点进程行的「终止」：

1. 弹窗显示目标 PID、属主、环境、显存、命令行
2. 在输入框填入目标 PID 数字以二次确认（防止点错）
3. 系统先发优雅终止信号；宽限期内未退出则**强制终止**，全程写审计
4. 终止结果经实时推送提示（优雅退出 / 强制终止 / 目标已消失等）

### 4. 节点管理

- **重验**：修改凭据后重试，或做常规体检
- **维护**：维护模式下不参与统计，显卡状态转为未知
- **删除**：有活动进程的节点默认阻止删除；勾选「强制下线」并填写原因后，系统逐进程走两段式终止再删除节点
- **凭据轮换**：编辑节点可直接更新 SSH 用户名/密码

### 5. 审计日志

按动作 / 操作者 / 目标关键词筛选，默认展示最近 200 条。记录登录、终止、绑定、删除、维护、硬件变更等全部关键动作。

## 配置项（环境变量，全部可选）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `9286` | 服务端口 |
| `POLL_INTERVAL_SEC` | `5` | 采集/刷新周期（秒） |
| `KILL_GRACE_SEC` | `30` | 优雅终止宽限期（秒） |
| `IDLE_MEM_THRESHOLD_MB` | `500` | 空闲判定显存阈值（MB） |
| `HEARTBEAT_FAILS` | `3` | 连续 N 次采集失败 → 节点离线 |
| `SSH_TIMEOUT_SEC` | `15` | 单步 SSH 超时（秒） |
| `SESSION_HOURS` | `12` | 会话闲置过期（小时） |
| `LOGIN_MAX_FAILS` | `5` | 连续登录失败锁定阈值 |
| `LOCK_MINUTES` | `15` | 登录锁定时长（分钟） |
| `KILL_RETRY_PER_MIN` | `3` | 同一进程 1 分钟内重试上限 |
| `INITIAL_ADMIN_USERNAME` | `adminxt` | 首次启动预置管理员用户名 |
| `INITIAL_ADMIN_PASSWORD` | `XieTong0504@` | 首次启动预置管理员密码（≥10 位，含字母与数字） |
| `DATA_DIR` | `./data` | 数据目录（节点档案/审计/会话，自动生成） |

示例：`KILL_GRACE_SEC=8 PORT=9000 node server/index.js`

## 平台说明

- **Linux 节点**：`nvidia-smi` + `/proc` 采集；`kill -TERM/-KILL` 两段式终止。每进程显存、属主、命令行完整可得
- **Windows 节点（本机直连）**：`nvidia-smi`（PowerShell 包裹）+ `Win32_Process` 采集；`taskkill` → 宽限期 → `taskkill /F` 两段式终止
- Windows WDDM 显卡模式下，驱动不提供每进程显存数值（`nvidia-smi` 显示 N/A），系统如实显示 0；**卡级已用显存不受影响，空闲/占用判定以卡级数据为准**

## 安全说明

- 管理员密码 bcrypt 加密存储；节点 SSH 凭据 AES-256 加密落盘，接口永不回显
- 全部 API（登录除外）需会话认证；会话闲置 12 小时过期
- 审计日志只增不改不删，终止/删除/登录等关键动作全部留痕
- 生产部署建议：仅放内网，或置于 HTTPS 反向代理之后；定期修改管理员与节点凭据

## 常见问题

- **页面打不开**：确认端口没被占用（`PORT` 换一个），防火墙放行端口
- **节点一直「接入验证中/失败」**：先在目标机器上手动跑 `nvidia-smi` 确认驱动正常；再检查 SSH 账号密码、端口、防火墙
- **节点频繁转离线**：看节点管理页的失败原因（SSH 超时/驱动错误），网络抖动时可调大 `SSH_TIMEOUT_SEC`
- **终止后显存没回落**：等 1-2 个采集周期（默认 5 秒）刷新；仍未回落说明进程被系统托管，可再次发起终止（1 分钟限 3 次）
- **忘记管理员密码**：删除 `data/admin.json` 后重启，系统会按预置初始账号重建（审计数据保留）
